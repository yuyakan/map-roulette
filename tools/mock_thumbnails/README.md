# App Store スクショ撮影用のモックサムネ

トレンド機能のサムネ・タイトル・チャンネル名を、撮影のあいだだけ
自前のダミーに差し替えるための道具。

## なぜ要るか

アプリ内で YouTube の動画を出すこと自体は規約上まったく問題ない
（公式埋め込み・出典表記・30日ルールをすべて満たしている）。
別なのは **App Store の販促素材に他社コンテンツを載せること**で、次の2つに触れる。

- **Apple**: 他社の商標や実在人物の顔が写る／第三者コンテンツがアプリの売りに見える
  （Review Guidelines 2.3 系。スクショは「アプリが実際に提供するもの」を写す）
- **YouTube**: ブランド利用のガイドラインは、アプリ内表示とプロモ素材で別の制約を課す。
  アプリ内で正しく出典表記していることは、スクショで使ってよい根拠にはならない

さらに、**サムネは CC ライセンスではない**。アプリ内表示は埋め込みの一部として
許容されるが、マーケティング素材への転用はその根拠から外れる。

## 使い方

Xcode > Product > Scheme > Edit Scheme… > Run > Arguments >
"Arguments Passed On Launch" に追加して実行する:

```
-MRScreenshotMode YES
```

撮影が終わったらチェックを外すだけ。コードは元に戻さなくてよい。

`#if DEBUG` で囲ってあるので **Release ビルドでは常に無効**。
有効なまま提出用バイナリを作ることは構造的に起きない
（Release バイナリに `MRScreenshotMode` / asset 名 / ダミー文言が
現れないことを `strings` で確認済み）。

## 差し替わる範囲

`CachedThumbnail` 1箇所で差し替えているので、ホーム・県詳細・Shorts の
プレースホルダがまとめて置き換わる（すべてこのビューを経由している）。
文言は `TrendVideo.displayTitle` / `displayChannelTitle` 経由。

割り当ては djb2 の安定ハッシュなので、**同じ動画には常に同じ絵・同じ文言**が出る。
撮り直しても並びが変わらない（`hashValue` は実行ごとに変わるので使っていない）。

## 画像の作り直し

```
python3 gen.py          # カレントに mock_trend_*.jpg が出る
```

出力を `MapRoulette/Assets.xcassets/MockThumbnails/<名前>.imageset/` に置く
（imageset の `Contents.json` は既存のものをそのまま使ってよい）。

### 画像を足す・差し替えるときの原則

1. **実在の動画サムネに似せない。** 人物・ロゴ・文字・実在スポットの写真は入れない。
   幾何形状だけの抽象的な風景にする。実在コンテンツの偽装は「誤解を与えるスクショ」
   そのものになり、避けようとしている問題を作り直すことになる。
2. 9:16（720×1280）。カードもプレイヤーも縦型。
3. 追加したら `ScreenshotMode.mockAssets` にも名前を足す。

現在の9枚: カフェ / 丼 / 山 / 海 / 夜景 / 祭り / 温泉 / 鳥居 / 桜と城（計 680KB）。

## スクショに何を写すか（参考）

トレンドを避けても見せ場は足りる。むしろこちらのほうがアプリの価値に近い。

- 都道府県ルーレット（回転中・結果）… アプリの核
- 日本地図（重み付けの色分け）
- 県詳細の写真ヘッダー … CC BY/CC0 で権利処理済み（`tools/photo_pipeline/`）
- 温泉 / 自然 / 祭りのマップ、マイプラン、近くのスポット

ホームを使いたい場合も、トレンド帯より上（ルーレット導線・最近見た県・
お気に入り）でフレーミングすればサムネを写さずに撮れる。
