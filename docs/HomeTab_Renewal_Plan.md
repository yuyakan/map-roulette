作成日: 2026-09-08
対象: MapRoulette iOS (SwiftUI) + トレンドバッチ (maproulette-trend-batch)
前提: 初期実装は `docs/HomeTab_Trend_ImplementationPlan.md`（P0〜P4完了済み）を参照。本書はその後継リニューアル。

## 0. 背景と問題（なぜ作り直すか）

現在のホームタブは **エリア(15) × カテゴリ(3) = 最大45行**を機械的に縦へ並べているだけ。
これはバッチのデータ構造（エリア×カテゴリの総当たり）を、そのまま画面に写したもの。

ユーザー視点の問題:
- 45行フラットで、どこを見ればいいか手がかりがない
- 自分に関係あるエリアに辿り着くのに大量スクロール
- 優先順位・文脈がなく「意味がわからない」

**根本原因**: データの持ち方とUXが1:1。並べ方に「ユーザー由来の意味」がない。

---

## 1. 目的とコンセプト（合意済み）

- **ホームタブの主目的**: ユーザーが求めるものに最短アクセスする玄関。**検索させない**。
- **動画は主役のまま活かす**。変えるのは「どの動画を・どの順で・どんな見出しで出すか」。
- ユーザーの行動（最近見た県 / お気に入りの県）を**並び替えと絞り込みの軸**に使う。
- 各ブロックは「動画 + その県への導線」がセット。動画を孤立させず、既存の
  県詳細画面（`TourismDetailView`）や他タブ機能へ流れる**ハブ**にする。

### 役割分担
- **マップタブ**: 能動的に「行き先を探す/決める」。県を選ぶ→県詳細→動画。
- **ホームタブ**: 受動的に「既に関心があるものへ最短で戻る」。パーソナルな動画棚。

## 2. 最大の設計変更: バッチを「県単位」に作り直す（合意済み）

現状: 動画は15エリア単位（東北=複数県まとめ、箱根/鎌倉/宮島=観光地）で、県(47)と1対1でない。
→ 「最近見た県の動画」を引こうにも対応する動画がない空振りが多発する。

**決定**: バッチを **47都道府県単位**（`Prefecture.rawValue` をキー）に作り直す。
これで「県 → 動画」がクリーンに引け、ホーム・県詳細・マップが同じ `Prefecture` 軸で統一される。

### 2.1 クォータ設計（合意済み）
- `search.list` = 100ユニット/回。無料枠 10,000/日 = **100検索/日が上限**。
- 47県 × 3カテゴリ = 141検索 → 枠超過。
- **採用方式: 県を2日でローテーション**。
  - 47県を 24県（群A） + 23県（群B） に分割。
  - 1日あたり **max 24県 × 3カテゴリ = 72検索 = 7,200ユニット/日**（枠内・余裕あり）。
  - 各県の更新は **2日に1回**。
- 注意: 手動実行(`workflow_dispatch`)をその日に足すと +7,200。3カテゴリなら合算14,400で超過するので手動実行時は注意。

### 2.2 カテゴリ（合意済み・3カテゴリ）
| categoryKey | 表示名 | 検索クエリ(query) |
|---|---|---|
| cafe | カフェ | `カフェ` |
| spot | 映えスポット | `映えスポット` |
| gourmet | グルメ | `グルメ` |

- 当初 stay(`ホテル\|旅館` OR検索)を4つ目に検討したが、1ドキュメント1MiB制約と
  47県×30件維持の両立のため**3カテゴリに確定**（stayは見送り）。
- 1グループ **30件** 維持。タイトルは40文字切り（既存の `TITLE_MAX_CHARS`）。

### 2.3 ローテーションの実装方針
- `areas_categories.json` を県定義（47県）に置き換え。エリア概念は廃止。
- 47県を群A(24) / 群B(23) に固定分割。実行日から群を決定（例: `dayofyear % 2`）。
- **その日の群を丸ごと作り直して、対応する集約ドキュメントに1回 set**。
  - ローテ群とドキュメントが1対1なので、前回値を読んで部分更新する必要がない（バッチが単純）。
- 今日更新しない群のドキュメントは触らない＝前回値が温存される（要件A: 更新2日に1回でも30日ルールに余裕）。

### 2.4 Firestore 構造（確定: 2ドキュメント分割）
集約は維持しつつ、**ローテ2群 = 2ドキュメント**に分割する。県ごと47個には**しない**
（読み書きが県数ぶん膨らむため却下）。

```
trends_bundle/groupA   … 群A 24県分（ローテ1日目に全上書き）
trends_bundle/groupB   … 群B 23県分（ローテ2日目に全上書き）
```

各ドキュメント内は現状の集約と同じ構造（`groups: [ {area→pref, category, updatedAt, videos[]} ]`）。

**容量試算（title40字・1動画≈421B・30件）**: 24県 × 3カテゴリ × 30件 ≈ **0.87MB** < 1MiB（余裕）。

**読み書き回数への影響（膨大化しない）**:
| 項目 | 従来(1doc) | 本方式(2doc) |
|---|---|---|
| アプリ読み込み | 1回 | 2回（groupA + groupB を読む）※無料枠5万/日に対し誤差 |
| バッチ書き込み | 1回 | 1回（その日の群のドキュメントだけ set） |
| バッチ読み込み | 1回 | 0回（群を丸ごと上書きするため前回値を読む必要なし） |

- アプリは起動時に2ドキュメントを読み、全県分を結合してから県ルックアップに使う。
- 各ドキュメントに `updatedAt`（要件A）。群Bは前日更新なので最大1日古いだけ。

## 3. アプリ側の変更

### 3.1 新ストア2つ（`VisitedPrefectureStore` が雛形）
既存 `Model/VisitedPrefectureStore.swift` が「県Set + UserDefaults + シングルトン」の完成雛形。

1. **`FavoritePrefectureStore`**（新規）
   - お気に入り県。`Set<Prefecture>`。トグルで追加/削除。UserDefaults永続化。
   - 雛形をほぼコピー。storageKey = `favorite.prefectures`。

2. **`RecentPrefectureStore`**（新規）
   - 最近見た県。**順序保持**（最新が先頭）・**上限10件**・重複は先頭へ繰り上げ。
   - `[Prefecture]`（Setではない）。`record(_:)` で先頭挿入＋重複除去＋上限トリム。
   - storageKey = `recent.prefectures`。

### 3.2 履歴記録の差し込み（1箇所）
- `Views/Tourism/TourismDetailView.swift` の `.onAppear` で
  `RecentPrefectureStore.shared.record(prefecture)` を呼ぶ。
- これで両入口（`JapanMapView` の県タップ / `PrefectureSearchView` の検索）を同時にカバー。

### 3.3 県詳細に動画セクション追加（"今後やる"部分）
- `TourismDetailView` に、その県の動画（`trends_pref/{prefKey}`）を出すセクションを追加。
- ホームと同じデータ源・同じ `TrendCard`/`ShortsFeedView` を再利用。
- 要件C/D（独自コンテンツ共存・出典表記）を踏襲。県詳細は独自コンテンツが豊富なので要件C安全。

### 3.4 HomeView 作り替え
現在の「45行フラット + `TrendSectionView`」をやめ、パーソナルな動画棚に再構成。

セクション構成（上から）:
1. **最近見た県**（最優先）: 直近で開いた県ごとに、動画サムネ数枚 + 県名 + 詳細導線。
   - 県名/ブロックタップ → `TourismDetailView(prefecture:)`（既存）
   - 動画サムネタップ → `ShortsFeedView`（既存）
2. **お気に入りの県**: ブックマーク県を同形式で。
3. **今アツい動画（トレンド）**: 人気動画を横断で1〜数段に凝縮（45行に割らない）。
   - 各動画からその県の詳細へも飛べる。
   - **要件C対応**: これがホーム内の独自コンテンツ（最近見た/お気に入り）と共存する形。

- 空状態: 最近見た県/お気に入りが空なら、トレンドや「県を探す」導線を出して玄関として成立させる。

### 3.5 お気に入り追加の導線
- `TourismDetailView` に「お気に入り」ボタン（`FavoritePrefectureStore.toggle`）。
- ホームの「お気に入りの県」セクションはここから育つ。

### 3.6 データモデル/デコード変更
- `TrendGroup`/`TrendVideo` を県単位に対応（`areaKey`→`prefKey` 等、キー名整理）。
- `TrendRepository` を「県キーで引く」ルックアップに。案X(県ごとdoc)なら複数doc読み取り。

- 要件D: `TrendCard`/再生画面にYouTube出典。
- 要件E: 60秒以下Shortsのみ・縦型9:16。
